## Faza 4 — Computer Use Windows MVP (P1) → repo `jev-cu` lub `jevskill/cu/`

**Cel:** pętla „cel → działanie" na Windows z budżetem kroku ≤ 500 ms tam, gdzie UIA pokrywa okno; porównanie z `kofanlabs/typesafe-computer-use-windows` na tych samych zadaniach.

Architektura (research §6.1):

```
UIA snapshot aktywnego okna (uiautomation / pywinauto, cache + StructureChanged)   10–60 ms
  → normalizacja + redukcja w kodzie (widoczne ∧ enabled ∧ rola interaktywna, dedupe, ≤ 60)  ≤ 2 ms
  → hash drzewa (stuck/changed w kodzie)                                          ≤ 1 ms
  → cache makr: (goal_norm, hash_norm) → decyzja                                  0 ms gdy trafienie
  → Jev fan-out (1 wywołanie, hedged)                                             ~300 ms
  → walidacja: element istnieje, bbox na ekranie, nie zasłonięty, op ∈ dozwolone dla roli,
    is_destructive ∧ conf < 0.85 → potwierdzenie                                  < 1 ms
  → UIA Invoke / SetValue, inaczej SendInput                                       ~5 ms
  → settle: event UIA lub zmiana hasha, cap 200 ms
OCR (Windows.Media.Ocr) tylko dla regionów bez UIA, asynchronicznie, wynik do następnego kroku.
Tekst do pól: mały LLM równolegle z Jev (pre-generacja na starcie zadania), Noul „sensible value" po wpisaniu.
```

| # | Zadanie | Kryterium |
|---|---|---|
| 4.1 | `cu/observe.py`: UIA → lista `{id, role, name, value, bbox, enabled, focused, patterns}`; pomiar czasu per okno (Notatnik, Eksplorator, Ustawienia, Chrome, VS Code) | tabela ms per aplikacja; pokrycie kontrolek jak w typesafe-computer-use (Finder 100% … Spotify 0%) |
| 4.2 | `cu/reduce.py`: filtr + dedupe + kaskada region→element gdy > 60 (skill_suggestion) | trafność wyboru celu na 30 syntetycznych ekranów ≥ 95% |
| 4.3 | `cu/decide.py`: bundle pytań (`act.md`), progi per typ akcji, `none`, hedging | jeden POST na krok; `stuck` **nie** jest pytaniem |
| 4.4 | `cu/act.py`: UIA patterns → SendInput fallback; lista akcji nieodwracalnych (Delete, Send, Pay, Format, Uninstall) wymaga potwierdzenia niezależnie od conf | test: żadna akcja z listy nie wykonuje się bez `--yes` |
| 4.5 | `cu/loop.py`: stop: `done` ∨ `none` ∨ conf < floor ∨ 2× ten sam hash ∨ budżet kroków/czasu; log kroku: czasy etapów, tokeny, koszt, decyzja, hash | każdy run w `runs/<ts>/` z JSON per krok |
| 4.6 | `cu/macros.py`: cache (goal_norm, hash_norm) → decyzja, TTL, invalidacja przy braku zmiany hasha po akcji | powtórka zadania: 0 wywołań Jev |
| 4.7 | Benchmark: 10 zadań × 3 runy (Notatnik: zapisz jako; Eksplorator: nowy folder + zmiana nazwy; Ustawienia: tryb ciemny; Chrome: wyszukaj + otwórz wynik; Kalkulator: 12×34; …): czas, kroki, koszt, sukces; ta sama lista na `kofanlabs/typesafe-computer-use-windows` | `bench/cu_tasks.json` + `bench/cu_task_results.json`; README z tabelą i zastrzeżeniami (n=3, jeden host) |
| 4.8 | Eskalacja: `target=none` ∨ conf < floor → VLM (Claude computer use) albo człowiek; licznik eskalacji w raporcie | odsetek kroków eskalowanych w tabeli 4.7 |

Ryzyka (research §5): luki UIA (Electron/canvas) → OCR/VLM ≥ 600 ms; liczba kroków, nie grounding, decyduje o czasie zadania; nieznane dialogi/CAPTCHA → eskalacja. Każde ryzyko ma licznik w logu kroku.
Wykonawca: 4.1–4.6 Opus 5 high (rozłączne pliki, 3 równoległe worktree: observe+reduce, decide+act, loop+macros), 4.7 Sonnet 5 medium, przegląd całości Opus 5 high. Estymat: 3–5 dni.
